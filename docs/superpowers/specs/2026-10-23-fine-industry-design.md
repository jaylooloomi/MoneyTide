# 細產業分類（第 4 種分組）— 設計規格

- 日期：2026-10-23
- 狀態：依 docs/goal-prompt.md 的定案實作（子項目 ②）
- CMoney、XQ 的細產業是付費軟體的自家資料，沒有公開來源，因此不做、不爬。改用櫃買中心「產業價值鏈資訊平台」https://ic.tpex.org.tw （公開、政府機構營運）。

## 1. 來源與解析（`sources/tpex_chains.py`）

- 首頁列出約 40 條產業鏈：`introduce.php?ic=<代碼>`（半導體、被動元件、通信網路…）。
- 每條產業鏈頁面有隱藏的成員清單 `<div id="companyList_<id>" title="<子分類>">`。成員是 `company_basic.php?stk_code=<代號>` 連結；沒有台灣代號的外國企業連到自己的網站，自然不會被算進來。
- 每個清單在頁面裡出現兩次，以 id 去重。
- 部分子分類還有更細一層（例如 IC設計 → 電源管理IC、記憶體IC…）：`sc_link_<sid>` 是名稱，`sc_company_<sid>` 表格是成員。有細層時用最細一層。
- 群組名稱：
  - 有細層：「子分類／細分類」，例如「IC設計／電源管理IC」。
  - 沒有細層：「產業鏈／子分類」，例如「半導體／光罩」。
  - 名稱已被其他產業鏈使用時，加上本產業鏈名稱當前綴。
  - 「/」改成全形「／」、「,」改成「、」，避免破壞 URL 與 E 面板的逗號清單。
- 一檔股票可以屬於多個細產業。
- 抓取：首頁＋40 頁，每次間隔 3 秒，約 2 分鐘。首頁少於 30 條產業鏈就視為網站改版，報錯。

## 2. 載入與快取

- 直接重用 `ConceptLoader`（與概念股相同的背景載入、7 天快取、失敗每小時重試），快取檔為 `data/chains_cache.json`。
- 由 `create_app(start_concepts=True)` 一併啟動。

## 3. API

- `GET /api/chains/status`：與 `/api/concepts/status` 相同格式。
- `GET /api/groupings/chain`：代號 → 細產業清單（即時頁重新分組用）。
- 歷史 API 的 `grouping` 參數接受 `chain`（快取鍵為 `chain:<saved_at>`）。
- `GET /api/membership/{code}` 多回傳 `chains`。

## 4. 前端

- 歷史頁分組切換新增「細產業」按鈕：載入完成前停用，並顯示下載進度（與概念股共用同一段狀態輪詢程式）。
- 即時頁分組切換新增「細產業」。
- 即時與歷史個股卡多一行「細產業：…」。
- B～F、熱力圖、網址書籤（`#history/<date>/chain`）都支援這個分組。

## 5. 驗收

- 至少涵蓋 80% 的上市櫃普通股（以即時快照的 kind = stock 為母體，實測數字寫進報告）。
- 歷史頁切到「細產業」可以看 B～F。
- 測試：首頁／半導體頁 fixture 的解析、去重、細層命名、跨產業鏈撞名、首頁改版時報錯。
