# 族群連動性（K 面板＋B 連動R）— 設計規格

- 日期：2026-10-23
- 狀態：使用者選定三項都做；分時資料用「自己錄＋Yahoo 補過去」
- 目的：鎖定資金流入的族群後，判斷是「群體圍攻」還是「單兵作戰」，以及族群內有沒有「龍頭先動、二線跟上」的時間差。

## 1. 成員

- 族群內當天市值前 8 大的普通股（`history/linkage.py: top_members`）。

## 2. 日相關係數

- 過去 20／60 個交易日每天漲跌幅的兩兩 Pearson 相關，至少要有 10 個共同交易日；族群 R = 兩兩相關的平均。
- 判斷：R > 0.7 群體圍攻、R < 0.3 單兵作戰，其餘中度連動。
- B 排行新增「連動R」欄（20 日；跟著 `/api/history/flows` 一起回傳，每天快取）。

## 3. 分時資料

- **自己錄**（`intraday.py: IntradayRecorder`）：
  - 盤中（平日 09:00–13:40，含 13:35 收盤後那次）每次即時輪詢的快照版本更新時，存下每檔普通股的價格，表 `intraday_tick(date, ts, data)`，data 是 zlib 壓縮的 JSON `{代號: 價格}`。
  - 只保留最近 20 個交易日；解析度與輪詢頻率相同（預設 60 秒）。
- **Yahoo 補過去**（`sources/yahoo_intraday.py`）：
  - `query1.finance.yahoo.com/v8/finance/chart/<代號>.TW|.TWO?interval=5m&range=60d`，非官方接口。
  - 只在打開 K 面板、且那幾天沒有自錄資料時，替該族群前 8 大成員各抓一次，存 `yahoo_5m(code, date, bars)`，同一檔 6 小時內不重抓。
  - 抓取失敗只在 K 面板顯示提示，不會讓面板出錯。

## 4. 分時相關係數

- 最近 3 個交易日的 5 分 K（自錄資料以每 5 分鐘最後一筆價格當收盤）。報酬只在同一天內計算，不跨夜；三天串起來，至少要有 20 個共同點才計算。
- 判斷門檻用 0.5／0.2：5 分鐘報酬的雜訊遠大於日報酬，沿用 0.7／0.3 會讓幾乎所有族群都被判成單兵作戰。

## 5. 創高時間

- 選定那一天，每檔「第一次達到當天最高價」的時間（自錄用每筆價格，Yahoo 用 5 分 K 的最高價）。
- 創高時間標準差：≤ 10 分鐘高度同步、≥ 60 分鐘時間錯落，其餘普通。
- 龍頭領先：龍頭（市值最大）創高後，其他成員平均晚幾分鐘創高；負數代表龍頭最晚創高。

## 6. API 與畫面

- `GET /api/history/linkage?date=&grouping=&group=` →
  `{members, daily: {r20, r60, matrix20, matrix60}, intraday: {sessions: [{date, source}], r, matrix}, peaks, peak_std_min, leader_lag_min, verdict, notes}`
  - source 為 recorded／yahoo／none。
- K 面板（J 下方，整列寬度）：
  - 在 B 點選族群時出現，切換日期時跟著重算，切換分組時收起來。
  - 內容：摘要與判定標籤、日相關矩陣（20／60 日切換）、分時相關矩陣、創高時間軸（👑 標示龍頭，點名稱開個股卡）。

## 7. 測試

- Pearson、矩陣、判定、創高時間、5 分鐘分桶與同日報酬、Yahoo 解析。
- 記錄器只在盤中、快照版本更新時寫入。
- API 用預先存好的 Yahoo 資料，不連網。
